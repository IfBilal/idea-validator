# 14 — Testing Strategy

## 1. Pyramid
| Level | Tool | Where | Runs in |
|---|---|---|---|
| Unit | pytest (+ hypothesis) / Vitest | `services/*/tests/unit`, `services/ui/src/**/*.test.tsx` | every PR (GHA) |
| Component (UI) | Vitest + Testing Library + MSW | `services/ui/src/components/**` | every PR (required check) |
| Contract | pytest: Pydantic ↔ `schemas/*.json` drift; client ↔ server OpenAPI compatibility | `libs/common/tests`, `tests/contract` | every PR |
| Behaviour (agents) | pytest with recorded responses + PydanticAI `TestModel/FunctionModel` | `services/orchestrator/tests/behaviour` | every PR |
| Integration | pytest + testcontainers (Postgres, Redis, Qdrant) | `services/*/tests/integration` | every PR (if < 5 min) else Jenkins |
| Retrieval quality gate | pytest on snapshot | `eval/retrieval` | every PR (required) |
| Golden verdict vectors | pytest | `services/verdict/tests/test_vectors.py` | every PR (required) |
| Smoke (deployed) | `scripts/smoke_test.sh` (curl through Ingress: health of all, register/login, validate a fixture idea in replay mode) | cluster | Jenkins after deploy |
| E2E | Playwright (profile → validate → card → what-if → challenge) | `services/ui/e2e` | Jenkins nightly / before demo |
| Evaluation | eval harness Job | cluster | Jenkins nightly |
| Security | gitleaks, Trivy, pip-audit, npm audit, kube-linter, sanitiser corpus | CI | every PR |

## 3. Behaviour tests with recorded responses
- `RecordingTransport` (httpx) + PydanticAI `FunctionModel` → record once with `--record`, commit fixtures
  (sanitised, no secrets), replay by default. CI never calls a real model.
- Mandatory scenarios: invalid JSON from a scorer, tool timeout, empty source, poisoned page (Guide §7), plus approval
  declined, debate drop, budget stop, cache hit.

## 4. Coverage targets (enforced with `--cov-fail-under`)
M11 ≥ 95% lines + 100% of rule branches · M3, M5, M12 ≥ 85% · other services ≥ 70% · UI components ≥ 70%.

## 5. Test data
- `tests/fixtures/cards_small.jsonl` (≈ 200 cards from the snapshot, for fast tests).
- `eval/verdict/test_vectors.json` (generated by the reference engine; do not hand-edit).
- `eval/retrieval/queries.yaml`, `eval/labelled/labelled_set.jsonl`, `jobs/finetune/data/test.jsonl`.

## 6. Rules
- A bug fix starts with a failing test.
- Never mark tests `skip`/`xfail` to get green without an issue link + reviewer approval.
- Tests must not need internet or API keys (CI has none). Use recorded fixtures.
- Flaky test = bug: quarantine with issue, fix within a day.
