# scouts (M4): Scout agents

Collect raw items from official, keyless-first APIs and store them in `scouts.raw_pages` for the ingestion job (M6i).
Scouts **never** write cards and **never** touch the internet themselves: every request goes through M5 `POST /fetch`
(allow-list, SSRF guard, robots.txt, per-host rate limit, cache, sanitiser). Fetched text is data: it is cleaned and
length-capped, stored, and never interpreted.

| | |
|---|---|
| Module | M4, port 8000 |
| Probes | `GET /health`, `GET /ready` (database, M5 address, sources config), `GET /metrics` |
| On demand | `POST /scout {source, limit?, run_id?}` with `X-Internal-Token`; limit <= `SCOUT_MAX_LIMIT` (500), wall clock <= `SCOUT_TIMEOUT_S`, single-flight per source (409 while one runs), 404 unknown source |
| CLI | `python -m scouts --source <name> [--limit N]` (aliases `hn`, `ph`, `se`); exit 0 finished/skipped, 1 failed, 2 usage or config error |
| Scheduled | CronJobs `scout-<source>` (generated by `scripts/gen_k8s.py`), `concurrencyPolicy: Forbid`, `backoffLimit: 2`; network edge `scouts -> tools, postgres` only |

## Sources
| Source | Credential | Status |
|---|---|---|
| `hackernews` | none | Algolia `search_by_date` (Show/Ask HN, paged, resumable) + Firebase feeds |
| `github` | optional `GITHUB_TOKEN` | REST search by the topic list in `config/sources.yaml` |
| `lobsters` | none | `hottest`, `newest`, `/t/<tag>` JSON |
| `stackexchange` | none | API v2.3 `search/advanced` (content CC BY-SA 4.0, stored in `metadata.licence`) |
| `reddit` | **`REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`** (human creates the app, approval needed) | off; items marked `training_allowed: false` |
| `producthunt` | **`PRODUCTHUNT_TOKEN`** (human creates a developer token) | off |

Keys the human must create: see `docs/data-sources.md` (Reddit "script" app + access request; Product Hunt developer token).
Put them in the git-ignored `.env`; `scripts/create_secrets.py` copies them into the `app-secrets` Secret (empty = source off).
Never in git, never logged (`SecretStr`, redacted `repr`).

**Known limit (needs an M5 change first, tracked on M5):** before `M5_FORWARD_AUTH` may ever be enabled, M5 must bypass its cache and
logging for requests that carry headers, a body or a non-GET method, accept auth headers only for the credential's own host, and redact
`Authorization` / `access_token` everywhere. The flag refuses to start unless `M5_SUPPORTS_AUTH=true` is also set. Reddit and Product
Hunt stay disabled in `sources.yaml` and their CronJobs are suspended until then.

**Known limit (needs an M5 change):** today `/fetch` is GET-only and forwards no headers. Therefore Reddit (OAuth token POST, Bearer)
and Product Hunt (POST GraphQL, Bearer) raise `UnsupportedRequest` until M5 accepts `method/headers/body` (the client sends them
when `M5_FORWARD_AUTH=true`), and the optional GitHub token is dropped (keyless limits apply). Stack Exchange always gzips replies
and M5 refuses compressed answers: verify with the live test and, if refused, M5 must decode (bounded) or the source drops.

## Raw item (what connectors produce) and the `raw_pages` contract for ingestion
```
{source, url, title, text, created_at, score, platform, metadata}   # stars/votes/points are `score` (+ metadata.stars)
```
Table `scouts.raw_pages` (Alembic, own schema and version table `scouts.alembic_version`; run `alembic -c /app/alembic.ini upgrade head`,
K8s Job `migrate-scouts`):

| column | meaning |
|---|---|
| `id` bigserial | ingestion orders by it |
| `source`, `url` | unique together; a rerun refreshes the row, never duplicates it |
| `fetched_at` timestamptz | last time the scout saw it |
| `status_code` | 200 |
| `body` jsonb | the raw item above (sanitised, capped: title 300, text 8000 chars) |
| `content_hash` | sha256 of url+title+text (score changes do not count) |
| `processed` boolean | `false` on insert and whenever the text changed; **ingestion sets it to `true` only after a fully successful run** |

Read with `SELECT id, source, url, fetched_at, body FROM scouts.raw_pages WHERE NOT processed ORDER BY id` (note the **schema
`scouts`**: set `search_path` or qualify the table). Scouts never set `processed = true`.

`scouts.scout_state(source, cursor jsonb, failures, opened_at, last_run_at, last_status, last_error)` holds the resume cursor and the
circuit breaker (CronJob pods are short-lived). Cursors advance only when a feed was read to its end, so a partial run resumes.

## Safety rules of the stored data
- Entities are never decoded (`&lt;` stays `&lt;`), markdown images become `[removed: image link]`, leftover `<tag` openers are neutralised.
- `metadata` has a key whitelist, strings are capped at 64 chars, lists hold at most 30 scalars, nesting depth <= 2.
- Item urls must be http(s) on a public host: localhost, `.local`/`.internal`, private/loopback/link-local/CGNAT addresses and numeric
  tricks (`2130706433`, `0x7f000001`) are rejected. **Nobody may fetch a stored url outside M5.**
- Public project identifiers only: no author, username, submitter or owner is stored (a test scans every fixture), see `docs/data-sources.md`.
- Two HN stories with the same external url are both kept (the later one is keyed by its discussion url).

## Cursor semantics
A cursor moves only when a feed was read to its end. A budget stop, error, rate limit or Stack Exchange `backoff` leaves it where it was
(rows read before the stop are still stored; the next run re-reads and upserts them idempotently). A timed-out or cancelled run counts
as a failure for the circuit breaker and is persisted.

## Single flight and retention
Each run holds a Postgres advisory lock (`pg_try_advisory_lock(hashtext('scouts:<source>'))`) for its whole duration, so the CronJob and
`POST /scout` (any pod) never run the same source at once, and breaker state is never updated concurrently. CronJobs use `backoffLimit: 0`
(the breaker owns retries). Retention: `python -m scouts prune --older-than-days N` deletes **processed** rows older than N days
(unprocessed rows are never deleted); run it from a Job or CronJob when the table grows.

## Known limit
The scouts use the shared `DATABASE_URL` role (no dedicated least-privilege database role yet).

## Failure handling
- **Circuit breaker:** `BREAKER_THRESHOLD` (3) consecutive failed runs open it; runs are skipped (`circuit_open`, `scout_source_up=0`)
  for `BREAKER_COOLDOWN_S` (1800), then exactly one half-open probe run: success closes, failure re-opens.
- **Budgets per source** (`max_requests_per_run`, `max_items_per_run` in `config/sources.yaml`, plus `--limit`): a stop at the budget is
  graceful (`ok`), data so far is kept. 429/403 from the source or M5 stops the run at once (no retry loop).
- **Malformed items** are dropped and counted (`scout_items_total{outcome="dropped"}`); a wrong payload shape fails the run but keeps
  what was read (`partial`). An empty source is `empty`, logged as a warning, not a failure.
- Report statuses: `ok, empty, partial, failed, disabled, circuit_open`. Metrics: `scout_runs_total`, `scout_items_total`,
  `scout_requests_total`, `scout_flagged_pages_total`, `scout_source_up`, `scout_run_duration_seconds`.

## Layout
`src/svc_scouts/`: `api/` (route only), `services/` (runner, breaker, context, connectors), `repositories/` (Postgres),
`clients/` (M5), `models/`, `migrations/` (Alembic, shipped in the package), `testing.py` (fakes). `src/scouts/` is the CLI entry.

```bash
uv run pytest services/scouts -m "not integration"      # recorded fixtures only, no network
uv run pytest services/scouts/tests/integration         # real Postgres (testcontainers or TEST_DATABASE_URL)
SCOUTS_LIVE=1 TOOLS_URL=http://localhost:8000 INTERNAL_TOKEN=... uv run pytest services/scouts/tests/live   # opt-in, real M5
docker build -f services/scouts/Dockerfile -t scouts:$(git rev-parse --short=7 HEAD) .
```
