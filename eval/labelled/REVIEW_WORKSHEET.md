# Review worksheet for the human verdict labels

**STOP. Do NOT look at the `ai_draft`, `ai_confidence`, `ai_rationale` or `ai_cards` columns until you have
written your own label for every row.** Those columns are an AI first pass (`labelled_by: ai-draft`, see
`labelled_set.draft.jsonl`). They are not the labelled set and must not anchor you. Hide the four rightmost columns
(or the whole right side of the table) in your editor, spreadsheet, or by pasting the table into a sheet and
hiding the columns, then label.

## How to label (independently)

1. Make your own copy of the table (or edit on your own branch). Fill only YOUR column (`bilal` or `taimoor`) for
   every row with exactly one of `GO`, `PIVOT`, `NO-GO`, `INSUFFICIENT_EVIDENCE`.
2. Judge each idea for the stated student profile, using the knowledge base evidence (the snapshot in
   `data/snapshots/` or, after ingestion, a Validate run with the cache off), the gates in
   `docs/harness/08_VERDICT_ENGINE_SPEC.md` (evidence: >= 3 sources on >= 2 platforms; feasibility: hours;
   risk blocker; duplicate) and the score thresholds. Do not talk to each other or to the AI draft before finishing.
3. Convention question to settle together before labelling: when an idea has a hard legal/safety/feasibility
   blocker but the KB has no cards for it, is the label `NO-GO` (what a person would do) or
   `INSUFFICIENT_EVIDENCE` (what the engine's first gate does)? The AI draft used `NO-GO`.

## How to merge

1. Both humans finish their column. Only then reveal the AI columns and compare.
2. Where `bilal` and `taimoor` differ, discuss. Write the agreed verdict in `resolved` and put `discussion`
   (or whoever decided) in `resolved_by`. Where they agree, leave `resolved` and `resolved_by` empty (agreement is
   recorded automatically). Optionally put a one-line reason in `notes`.
3. Optional `category` column: leave empty to derive it from the final verdict (GO to clear_go, NO-GO to clear_nogo,
   PIVOT to borderline, INSUFFICIENT_EVIDENCE to thin_evidence). Fill it with one of `clear_go`, `clear_nogo`,
   `borderline`, `thin_evidence` to override, e.g. a hard-to-call GO is `borderline`.
4. Run `python eval/labelled/make_labelled_set.py` (add `--worksheet PATH` / `--out PATH` if needed). It writes
   `eval/labelled/labelled_set.jsonl` per `eval/labelled/README.md`, and refuses to run if a label is empty or not one
   of the four verdicts, if a difference has no `resolved`, or if any category has fewer than 10 items (add new
   candidate ids to `candidates.jsonl` and to this table first). It warns, but still runs, if one human's column
   matches the AI draft on every row (anchoring red flag).
5. Never edit `candidates.jsonl` after labelling starts (add new ids instead).
